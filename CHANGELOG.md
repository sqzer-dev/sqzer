# Changelog

## Unreleased

### Features

* **core:** `Image` with validated construction, `u8`/`u16`/`f32` samples, an ICC slot, and `to_u8` / `without_alpha` adapters
* **core:** `Decoder`, `Encoder` and `Metric` traits with `DecoderCaps` and `EncoderCaps` descriptors
* **core:** `Registry` with probe, decode and per-format encoder dispatch; the last encoder registered for a format wins
* **core:** `Format` extension, MIME and `encoder_features` lookups
* **core:** `EncodeParams` gains `subsampling`, `resolved()` and `codec_opts()`
* **core:** `InvalidInput`, `InvalidParams` and `Unsupported` error variants
* **core:** `Orientation` and `Image::apply_orientation`, the shared EXIF orientation transform decoders apply
* **codecs:** PNG decoder and encoder over `png` (MIT OR Apache-2.0)
* **codecs:** JPEG encoder over `mozjpeg-rs` (BSD-3-Clause)
* **codecs:** JPEG decoder over `zune-jpeg` (MIT OR Apache-2.0 OR Zlib): grayscale stays gray, EXIF orientation applied, ICC kept
* **codecs:** WebP decoder over `image-webp` (MIT OR Apache-2.0): lossy, lossless and the first frame of animations, EXIF orientation applied, ICC kept
* **codecs:** JPEG XL decoder over `jxl-oxide` (MIT OR Apache-2.0): 8-bit sources to `u8`, deeper ones to `u16`; a file with its own ICC profile keeps it, everything else is rendered to sRGB
* **codecs:** AVIF decoder over `avif-parse` (MPL-2.0), `re_rav1d` (BSD-2-Clause) and `yuv` (BSD-3-Clause OR Apache-2.0): 8, 10 and 12-bit, monochrome and alpha items. Desktop targets only, `rav1d` does not build for wasm32
* **codecs:** PNG encoder over `oxipng` (MIT): filter and colour-type search, `zopfli` at effort 10, ICC kept. Desktop targets only; the wasm32 build keeps the plain `png` writer because `oxipng` depends on the C library `libdeflate` (ADR-0002)
* **codecs:** WebP lossless encoder over `image-webp` (MIT OR Apache-2.0): RGB, RGBA, gray widened to RGB, ICC kept, `webp:predictor` option
* **codecs:** AVIF encoder over `ravif` (BSD-3-Clause) and `rav1e` (BSD-2-Clause): 8-bit input, 4:4:4, alpha item, 10-bit payload by default, `avif:alpha_quality`, `avif:bit_depth` and `avif:color_model` options. Builds on every target including wasm32. Refuses lossless, chroma subsampling and images carrying an ICC profile rather than approximating them
* **codecs:** codec option parsing is shared across backends; error messages name the option as `codec:key`
* **sqzer:** a lossy target with no explicit format now defaults to AVIF when the build has an AVIF encoder; a lossless target still defaults to PNG
* **codecs:** `DecodeOpts::apply_orientation` is honoured by the JPEG and WebP decoders; JPEG XL applies its own orientation field unconditionally
* **codecs:** `registry()` builds the registry from the active features, portable tier first
* **sqzer:** `Sqzer::run` decodes, picks an encoder and encodes, returning `Output`
* **metrics:** SSIMULACRA2 over `fast-ssim2` (BSD-2-Clause) behind the core `Metric` trait, plus `Reference`, the reference side precomputed once for repeated scoring. `u8` and `u16` samples are taken as sRGB, `f32` as linear light, gray is replicated, alpha is ignored
* **metrics:** `Search`, the target-quality bisection: whole-number qualities, a tolerance around the target, a hard cap of six encodes, an optional seed, and a report listing every trial. A target the encoder cannot reach returns the best candidate with `reached: false` and `capped: true`, never an error
* **core:** `Registry::has_decoder`
* **sqzer:** the default perceptual target is honoured: `Sqzer::run` searches the chosen encoder and returns the search report in `Output::report`. A lossless-only encoder meets any target without a search. A format this build cannot decode back is refused with `Unsupported`, and the default format steps around it (AVIF on `wasm32`)
* **sqzer:** golden SSIMULACRA2 tests for every encoder, so a dependency bump that degrades output fails CI
* **metrics:** `Search::seed_step`: a seed that misses now steps away by a caller-given distance, doubling until the target is bracketed, instead of bisecting toward the range end
* **metrics:** `seeds`, calibrated seed tables per backend and target, generated offline by `tools/calibrate` from CID22, GB82-SC and CLIC 2025 and committed as data. Tables for JPEG (`mozjpeg-rs`), AVIF (`ravif`) and lossy WebP (`libwebp`, for the native tier)
* **sqzer:** a perceptual target starts its search from the backend's seed table when there is one
* **tools:** `tools/calibrate`, the calibration harness on `codec-eval`: `sweep` writes the seed tables, `verify` measures the seeded search against the unseeded one on a held-out split. A standalone package, excluded from the workspace because `codec-eval` depends on the AGPL `dssim-core`
* **cli:** the `sqzer` binary, ADR-0003: one flat command with the six shapes of ADR-0001 D5. `-f` for one or several formats, `-t` / `-q` / `--lossless` / `--preset` / `--fast` for the target, `-e`, `--subsampling`, `--keep-icc`, `--no-auto-orient`, and `-x codec:key=value` as the only codec-specific path, checked against the backend before any file is touched
* **cli:** output placement: sibling file by default, `-o` file or directory, `--suffix`, `--template` with `{stem} {ext} {width} {height} {format} {quality} {dir} {name}`, `--in-place` with `--backup`, `-r` mirroring each input tree under `-o`. Output never overwrites input unless `--in-place`, and an output larger than its input is skipped unless `--force`
* **cli:** paths: an argument that exists is literal, one that does not and has glob characters is expanded in-process and case-insensitively, a trailing quote is stripped, the stem is everything before the last dot. `--files-from` with `-0`, `--include` / `--exclude` under `-r`, `-` for stdin to stdout
* **cli:** `-j` files in flight, bounded by a decoded-pixel budget of `--max-pixels * jobs / 4` so a folder of huge images cannot exhaust memory. Encoders stay single-threaded
* **cli:** `--json` writes one JSON Lines object per output and nothing else to stdout; `-n` decodes and plans without encoding; `--progress`, `--quiet`, `-v` for search trials, `-vv` for resolved codec options, `--color` with `NO_COLOR`. Exit codes 0, 1 (partial batch), 2 (arguments), 3 (nothing could be done)
* **cli:** terminal output: every error in clap's own style through one path, so build and argument errors are coloured like file errors; per-file lines with aligned columns, dim directories, bold output names, green or yellow size change; a summary line with counts, bytes and elapsed time after a batch. `anstream` and `anstyle` (MIT OR Apache-2.0, already in the tree through `clap`) handle the terminal check, `NO_COLOR` and Windows VT mode
* **cli:** a progress bar on stderr, drawn only on a terminal: one overall bar and one spinner per file in flight, coloured by stage (cyan reading and decoding, magenta encoding with the search trial and its score ticking through, green writing). `indicatif` and `console` (MIT)
* **sqzer:** `Sqzer::encode_with` reports each step to an observer as `Progress`; **metrics:** `Search::encode_with` reports each trial as it is scored
* **cli:** `--list-codecs` and `--list-codecs -v`, generated from the registry, and a rendering of `EncoderUnavailable` that names what this build has and which feature adds the rest. A `rimage` codec name as the first argument prints the equivalent `sqzer` line
* **core:** `Preset` (`web`, `thumbnail`, `archive`, `lossless`) as a target plus an effort
* **core:** `content::classify`, the content heuristic of ADR-0001 D5: few colours or large flat areas make a graphic, everything else a photo
* **core:** `DecoderCaps::name`, `EncoderCaps::name` and `EncoderCaps::options` describe each backend by crate name and the `codec_specific` keys it accepts; `Decoder::dimensions` reads width and height from the header without decoding
* **codecs:** every backend names itself, lists its options and reads header dimensions; `avif:alpha_quality=auto` is accepted as the spelling of the default
* **sqzer:** `Sqzer::decode` and `Sqzer::encode` split `run` so one decode can feed several outputs; `preset`, `fast`, `keep_icc`, `auto_orient`, `pick_format` and the `params` / `decode_opts` getters; `Output` carries `backend`, `tier` and `content`. A graphic with no explicit format now defaults to lossless WebP (PNG when the build has no WebP encoder) instead of AVIF
* **codecs:** the native tier, ADR-0004. `native-webp`: lossy and lossless WebP over `libwebp` through `webpx` (MIT OR Apache-2.0), ICC kept, `webp:alpha_quality` and `webp:sharp_yuv` options. `native-jxl`: JPEG XL encoding over `libjxl` 0.12 through `gamut-jxl` (MIT OR Apache-2.0), lossy and lossless, 8 and 16-bit, ICC kept, `jxl:container` option; quality maps to a Butteraugli distance the way `cjxl` does it. `native-avif`: AVIF encoding over `libavif` 1.0 and `libaom` 3.11 (BSD-2-Clause), 4:2:0, 4:2:2 and 4:4:4, monochrome for gray input, `avif:alpha_quality` option. `native-heif`: HEIC decoding over a system `libheif` (>= 1.17, LGPL, linked dynamically) through `libheif-rs` (MIT), 8, 10 and 12-bit, alpha, monochrome, ICC kept, the container's own rotation applied. `native-jpegli`: JPEG encoding over jpegli through the `jpegli` crate (BSD-3-Clause), progressive with adaptive quantisation. A native encoder takes its format over from the portable one; every native feature is a compile error on wasm32
* **core:** `Format::encoder_features` names `native-jpegli` next to `jpeg`
* **cli:** an unavailable-encoder message no longer names a native feature for a lossless request, since no native backend adds a lossless mode
* **sqzer:** golden SSIMULACRA2 tests cover every compiled-in encoder by backend name, native ones included
* **metrics:** seed tables for the native backends (`webpx`, `gamut-jxl`, `libavif`, `jpegli`), swept on the same corpus as the portable ones; a sweep now keeps the tables of backends it did not run
* **tools:** `tools/calibrate` sweeps the native backends with `--features native`; its stand-in `libwebp` encoder is gone now that `native-webp` exists
* **workspace:** native CI jobs on the six desktop targets (all five backends on x86_64 Linux and macOS, four on aarch64 Linux, three on Windows, two on musl), `cargo deny` bans `jpegli-rs`, `jpegxl-rs` and `jpegxl-sys`, MSRV 1.92
* **codecs:** HEIC through OS decoders and a runtime-loaded `libheif`, ADR-0005. `native-heif` no longer links `libheif`: on macOS it registers ImageIO (`imageio`, through `objc2-image-io`, Zlib OR Apache-2.0 OR MIT), on Windows the Windows Imaging Component (`wic`, through `windows`, MIT OR Apache-2.0), and everywhere but musl `libheif` loaded at run time (`libheif`, through `libloading`, ISC), OS decoder first. A binary built with the feature starts on a machine without `libheif`; `--list-codecs` and the error for a HEIC input say what this machine has. `libheif-rs` is gone, and with it the `pkg-config` and vcpkg build steps
* **codecs:** the HEIC container is parsed in safe Rust in every build: brands, the displayed size after `clap` and `irot`, the orientation from `irot` and `imir`, and the ICC profile from `colr`. Every HEIC decoder takes those from the same walk, so the three agree on them by construction; a portable build recognises HEIC and answers `DecoderUnavailable` naming `native-heif` instead of `UnknownFormat`
* **core:** `Error::DecoderUnavailable`, `Format::decoder_features`, `Decoder::available` and `Registry::identify` and `register_sniffer`. The registry skips a decoder that cannot run on this machine and reports every reason when none can; `has_decoder` counts usable decoders only
* **codecs:** the input-only formats the README listed: GIF over `gif` (MIT OR Apache-2.0; first frame composed onto the logical screen, animation reported), TIFF over `tiff` (MIT; 8 and 16-bit gray, gray-alpha, RGB and RGBA, palette expanded, `f32` samples, the `Orientation` tag applied, the ICC tag kept, CMYK and YCbCr refused), BMP, TGA, ICO, QOI and PNM over `image`'s decoders (MIT OR Apache-2.0; 8 and 16-bit), and SVG rasterised by `resvg` (Apache-2.0 OR MIT) at the document's own size with the system's fonts on desktop targets. One feature per format, all in `portable`
* **core:** `Format::Bmp`, `Tga`, `Ico`, `Qoi` and `Pnm`; `decoder_features` names the feature for every input-only format
* **sqzer:** the resize stage of ADR-0001 D3 over `fast_image_resize` (MIT OR Apache-2.0). `Sqzer::max_width`, `max_height` and `resize` fit the image inside the bounds, keep the aspect ratio and never enlarge; `Sqzer::transform` is the new step between `decode` and `encode`, and `run` is the three in order. Lanczos3 in linear light with premultiplied alpha, for every layout and sample width; orientation is applied before it and a perceptual target is scored against the resized image
* **core:** `Resize`, the bounds and their geometry, `Preset::resize` and `Error::Transform`. The `thumbnail` preset now fits the image inside 512 x 512
* **sqzer:** the colour stage of ADR-0007 over `moxcms` (BSD-3-Clause OR Apache-2.0): an image carrying an ICC profile is converted to sRGB and the profile dropped, before the resize and the metric. `keep_icc` passes samples and profile bytes through untouched. `u8` and `u16` convert in their own depth, `f32` takes the primaries of a matrix-shaper profile; a profile that does not fit the layout is dropped, one that cannot be parsed is `Error::Transform`
* **core:** `Image` carries `Metadata`: the ICC profile, EXIF (as a TIFF blob from the byte-order mark) and XMP; `Image::apply_orientation` resets the EXIF `Orientation` tag so kept EXIF never contradicts the pixels; `EncodeParams::keep_metadata`; `EncoderCaps::exif` and `xmp`
* **codecs:** the JPEG, WebP, PNG and JPEG XL decoders attach EXIF and XMP, TIFF attaches XMP; the JPEG XL decoder resets the Exif box's orientation since the codestream's own field is what `jxl-oxide` applies. Encoders embed what the image carries: `mozjpeg-rs`, `jpegli`, `image-webp`, `webpx`, `png`, `oxipng` and `gamut-jxl` take both, `ravif` takes EXIF and refuses XMP, `libavif` refuses both
* **sqzer:** the metadata stage of ADR-0001 D7: EXIF and XMP are stripped after the colour conversion unless `Sqzer::keep_metadata` is set
* **cli:** `--keep-metadata`; `--list-codecs` says which blobs each encoder can carry
* **codecs:** OpenEXR decoder over `exr` (BSD-3-Clause, `rayon` off): RGB, RGBA and luminance layers, half and float samples, to `f32` linear light; a `chromaticities` attribute other than Rec.709 becomes a matrix-shaper ICC profile (built with `moxcms`) that the colour stage applies, malformed chromaticities are an error; deep data, layers past the first and pixel aspect ratios are not handled, alpha is read as stored
* **core:** `Format::Exr`; `Image::to_u16` and `linear_to_srgb`, the range policy for float input: sRGB-encoded 16-bit, clipped at display white, no tone mapping
* **sqzer:** float samples are converted to 16-bit sRGB in `Sqzer::transform`, so every encoder takes an OpenEXR input and the metric scores what the encoder gets; a float image that keeps its ICC profile under `keep_icc` is refused rather than left with a profile that no longer describes it
* **cli:** `--max-width` and `--max-height`; either one replaces the `thumbnail` preset's box. `--json` gains `output_width` and `output_height` next to the input's `width` and `height`, `{width}` and `{height}` in `--template` are the output's, and a dry run prints `4000x3000 -> 1600x1200`
* **workspace:** the release matrix on `cargo-dist` 0.33, ADR-0006. A `v*` tag builds the native tier for the six desktop targets and publishes the archives, a shell and a PowerShell installer and a Homebrew formula (`sqzer-dev/tap/sqzer`) that depends on `libheif` for the runtime loader
* **sqzer:** `native` on `sqzer` and `sqzer-cli` now means the backends the target can build and run, decided per target in the new `sqzer-native-tier` crate: all five on x86_64 Linux and macOS, no jpegli on Windows and aarch64 Linux, neither jpegli nor JPEG XL on musl. A single `native-*` feature stays strict and fails to build where the backend cannot
* **core:** `Orientation::then` composes two orientations, the way a HEIF lists `irot` and `imir` in sequence
* **cli:** `--list-codecs` prints an unavailable decoder with its reason and `none; needs \`native-heif\`` for an input-only format no feature reads; the JSON listing carries `decoder_features` and, on the decoder, `available` and `reason`
* **workspace:** three binding crates, `heif-dl`, `heif-imageio` and `heif-wic`, hold the workspace's `unsafe` behind a safe two-call API each; `sqzer-codecs` stays under `forbid(unsafe_code)`. `native-heif` now builds in CI on Windows and on musl (where it registers nothing), and the Windows job lists the Store codec packages the runner has
* **workspace:** scaffold, feature tiers, CI and the licence allow-list
